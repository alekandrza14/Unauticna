# AssemblyCPP / Perlin — оптимизированное обновление

Это отдельная библиотека шума; гиперболический космос её не вызывает.

## Установка

1. Закрой Unity перед заменой загруженной DLL.
2. Открой `AssemblyCPP.sln` в Visual Studio 2022 с C++ build tools и Windows SDK. Выбери **Release / x64**, собери проект. Альтернатива: запусти `BuildRelease.bat` из **x64 Native Tools Command Prompt for VS 2022**.
3. Результат: `AssemblyCPP/bin/x64/Release/AssemblyCPP.dll` относительно корня архива. Замени **существующую** AssemblyCPP.dll в Unity. Для новой установки используй `Assets/Plugins/x86_64/`. Не оставляй дубликаты DLL в других папках Assets.
4. Замени существующий `AssemblyCPPMath.cs` файлом из папки `Unity`. Отдельно скачанный AssemblyCPPMath.cs идентичен ему — нужна только одна копия класса.
5. Импорт DLL: Windows Editor и Windows Standalone x86_64. Перезапусти Unity.

Готовая Windows DLL в архив не включена: MSVC/Unity здесь не запускались. Все исходники проекта сохранены, промежуточные файлы сборки и кеш IDE не включены. Старые экспортируемые функции сохранены, C ABI шума не менялся. Новая C#-обёртка совместима и с прежней DLL, но ускорение самого шума потребует пересборки C++.

## API

Старый вызов работает; теперь выделяется один большой массив без промежуточного копирования:

```csharp
float[,] map = AssemblyCPPMath.PerlinNoise_2DMFloat(0f, 0f, 256, 128);
float height = map[10, 20];
```

Для повторной генерации выдели буфер один раз:

```csharp
float[,] map = new float[256, 128];
AssemblyCPPMath.FillPerlinNoise2D(map, 0f, 0f, 0.01f);
// Следующий блок — тот же массив:
AssemblyCPPMath.FillPerlinNoise2D(map, 256f, 0f, 0.01f);
```

Плоский буфер и фоновый запуск:

```csharp
float[] buffer = new float[256 * 128];
await AssemblyCPPMath.FillPerlinNoise2DAsync(buffer, 0f, 0f, 256, 128);
float height = buffer[10 * 128 + 20];
```

Не запускай задачу каждый кадр. Дождись завершения перед чтением, передачей массива в Unity или повторным заполнением того же буфера. Отмена проверяется до входа в DLL; уже начатый нативный расчёт заканчивается обычным образом. Несколько задач могут работать с **разными** массивами. Unity API вызывай на главном потоке.

Прямое заполнение выполняется через кратковременное закрепление GCHandle, `unsafe` не требуется. Фоновый метод использует ThreadPool; ядро C++ одного запроса последовательно, конкурентные запросы с отдельными массивами допустимы. Старые Fibonacci-функции по-прежнему имеют общее состояние и не предназначены для конкурентного изменения.

## Что изменилось

- C++ рассчитывает координаты и Fade по оси Y один раз и повторно использует хеши градиентов внутри ячейки. Для очень маленьких запросов остаётся прямой цикл без кеша.
- C# больше не создаёт промежуточный `float[]` перед `float[,]` и не делает `Buffer.BlockCopy` всей карты.
- Добавлены синхронные перегрузки заполнения существующих `float[,]` и `float[]`, а также фоновый метод.
- Release x64 явно использует MaxSpeed и Precise; результат сборки находится в отдельной папке `bin`.

Кеш оси Y в C++ временно выделяет примерно `24 * sizeY` байт. Поэтому «повторное использование без нового большого массива» относится к C#; это не обещание полного отсутствия нативных выделений.

## Формат и совместимость

Точка шума = `((x + ix) * scale, (y + iy) * scale)`, scale по умолчанию 0.01.
Размерность `[sizeX, sizeY]`, индексы `[x,y]`; плоский индекс `ix * sizeY + iy`.
Результат 0..1, детерминированный градиентный Perlin с фиксированным хешем; это не побитовая копия `Mathf.PerlinNoise`.
На целых координатах шума значение 0.5. Для соседних блоков с общим краем смещай начало на `sizeX-1`.
`TerrainData.SetHeights` использует `[y,x]`, перед ним транспонируй карту.

C ABI прежний:
`int PerlinNoise_2DMFloat(float x, float y, int sizeX, int sizeY, float scale, float* output, int outputLength)`; cdecl; outputLength — количество float.
Коды: 0 — успех, 1 — недопустимые аргументы/координаты, 2 — малый буфер, 3 — не удалось выделить временный буфер.
Масштабированные координаты должны быть в `[-2147483648, 2147483647)`. Исходные координаты этого Perlin — float; это не Decimal256 космоса.

## Проверки

Проверены 250 карт разных размеров, смещений и масштабов: float-результаты побитно совпали с исходным C++ ядром; проверены границы массивов, недопустимые аргументы и 8 конкурентных вызовов с отдельными буферами.
Реальный P/Invoke проверен на Linux-тестовой библиотеке с тем же C ABI: закреплённый `float[,]`, плоский массив и его хвост, повторное заполнение, async/отмена. В тесте .NET 8 сто повторных заполнений существующего массива дали 0 новых managed-байт; это не замер Unity Mono/IL2CPP.

CPU-замер C++14 / g++ -O2, без fast-math и FMA contraction, медиана 7 серий по 5 вызовов после прогрева, scale=0.01:

| Размер | До | После |
| --- | ---: | ---: |
| 512 × 512 | 3.40 мс | 2.86 мс |
| 1024 × 1024 | 15.05 мс | 12.33 мс |

Windows MSVC DLL, Unity Editor и графический результат здесь не проверялись. Эти числа относятся к отдельному ядру шума и не означают ускорение всей игры на столько же.
